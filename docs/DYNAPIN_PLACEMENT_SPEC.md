# DynaPin 配置最適化の実装仕様

2026-09-14 時点の作業ツリーの実装に基づく説明。全体の責務は [DYNAPIN_SPEC.md](DYNAPIN_SPEC.md)、型・API・所有関係は [クラス設計・プログラム仕様](DYNAPIN_PLACEMENT_PROGRAM_SPEC.md)、配置最適化の当初設計と履歴は [既存の設計記録](superpowers/specs/2026-08-26-dynapin-placement-optimization-design.md) を参照する。本書は実装済みの振る舞いを中心にし、将来案は末尾で分ける。

## 何を最適化するか

対象は現在のプレート上にある一つのモデルインスタンスである。元の姿勢を基準に、ワールド座標での **Z 軸相対回転 θ** と **Y 方向相対移動 Δy** を変える。独立した Δx 探索はしない。回転中心を固定する行列演算では X オフセットも変わり得るが、それは中心保持の結果である。

目的関数は **候補をDynaPinでスライスした後の、現在プレート全体の通常サポート幾何体積（mm³）**。対象インスタンスだけの体積ではない。他のインスタンスは位置を固定したまま評価に含む。ピンの本数、推定造形時間、G-code 長、造形品質は直接の目的関数にしない。造形物とピンの不適合は、既存の自動選択で衝突ピンを除くことで扱い、衝突するピンが一つあっても候補姿勢全体を直ちに棄却しない。

探索を始める条件は、FFF・現在プレートの `Print` が存在・DynaPin サポート最適化と配置最適化が有効・実効 debug stage が 1 以上・手動ピン選択なし・対象が Normal サポートあり・対象インスタンスが一つに確定、である。GUI で一つの完全なインスタンスを選択している場合はそれを使う。未選択の場合、現在プレートの印刷対象がちょうど一インスタンスならそれを採用する。Tree/Organic サポートと複数候補の曖昧な選択は対象外。

## 処理の全体像

```text
Plater::reslice()
  └─ start_dynapin_placement(): GUI 上の現在状態をスナップショット化
       └─ DynaPinPlacementJob::process(): ワーカーで探索
            ├─ 現在姿勢を完全評価
            ├─ 回転別の Y 範囲・粗候補を生成
            ├─ 粗候補を評価し上位 5 件を選択
            ├─ その周辺を局所評価
            └─ 有意に改善する候補だけ Improved
       └─ finalize(): UI スレッドで結果を検証・適用
            └─ 一回限りのガードを立てて通常の reslice を再開
```

## 入力と座標系

`PlacementSceneSnapshot` はコピーされた `Model` と印刷設定、対象 object/instance の `ObjectID`、初期変換行列、初期ワールド中心、現在プレートの印刷可能ポリゴン・高さ・原点・番号を持つ。`Plater` の生きたモデルをワーカーから読まないための境界である。`PlacementSearchInput` は `pitch_y`、現在姿勢、Y の実行可能範囲、角度ごとの範囲計算関数、評価関数、並列数などを持つ。GUI は `pitch_y = DynaPin::Config::col_pitch_y`、現在姿勢を `(0°, 0 mm)` として渡す。したがって θ はモデルの絶対角ではなく、開始姿勢からの相対角である。

候補行列は次式で毎回 **初期行列** から計算する。前候補への変換を累積しない。

```text
T_candidate = Translate(0, Δy, 0) · Translate(center) · RotateZ(θ)
              · Translate(-center) · T_initial
```

印刷可能範囲は現在プレートの形状と高さから作る。角度ごとの粗い Y 範囲は、θ を適用した対象モデルの bounding box とベッドの Y 最大・最小から `bed_min_y − bbox_min_y` ～ `bed_max_y − bbox_max_y` を求める。この段階は矩形的な予備制約であり、実際の候補評価では `BuildVolume` によるプレートポリゴンと高さの判定も行う。X 方向にベッドを外れる候補は Δx で救済しない。スライス後には、インスタンス同士の同じ Z 区間におけるモデル断面の重なりとベッド除外領域との交差も棄却する。

## 候補の作り方

`placement_delta_y_interval()` は実行可能 Y 範囲から最大で **1 col pitch 分** を取り、原則として `[-pitch/2, +pitch/2]` を中心にする。片側がベッド端に当たると区間を反対側へずらして幅を維持し、両側が狭ければ可能な幅だけを使う。`col_pitch_y` の符号は絶対値にする。現在姿勢はこの区間の外にあっても別途評価する。

粗探索では θ を `0, 5, …, 355°` の 72 通り、Δy を各角度の区間で `pitch/16` 刻みに生成し、区間端点も明示的に加える。角度ごとに Y 範囲を再計算する。各候補は正規化された回転角と約 `1e-7` の座標粒度で重複除去する。現在姿勢は先に評価済みなので粗評価では重複させない。

粗探索の実行可能候補を体積昇順に並べ、上位最大 5 件を局所探索の種にする。各種の周りで角度は `−4° … +4°` を 1° 刻み、Δy は `−4 … +4 × pitch/64` を評価する。1 種につき最大 81 候補だが、重複は除く。局所候補も `BuildVolume` 等の完全評価を通す。局所探索は離散的な近傍探索であり、全空間の大域最適性を保証しない。

## 一候補をどう評価するか

現在姿勢の評価ではスナップショットから `Model` と `Print` を作り、対象インスタンスへ候補行列を適用する。まず印刷可能領域を判定し、`Print::apply()` の後にサポート幾何専用の処理を呼ぶ。これは perimeter、infill 等の準備を含むが、押出経路や最終 G-code を生成するフルスライスではない。サポート生成直前に `Print::update_dynapin_selection()` が候補姿勢に対して自動ピン選択を再計算する。これにより候補ごとにピン選択とサポート除外が変化する。

実際のジョブは角度別評価器も作る。同一 θ の候補群について、`Model`/`Print` の作成とスライス準備を共有し、Δy ごとに現在位置・ピン選択・サポート幾何を再計算する。この再利用は探索時間を抑えるためであり、候補ごとの評価意味を変える意図はない。`evaluate_scene_candidate()` は単体の完全評価 API として残り、テストでは角度別評価との一致も確認している。

サポートの top/bottom contact、intermediate、interface 等から Z 区間とポリゴンを `SupportSlab` として集める。RaftBase/RaftInterface は除外する。ポリゴンは各インスタンスの plate-local shift を加え、同じ高さ区間で重なる領域を union して二重計上を避ける。体積は次で求める。

```text
volume = Σ［隣接する Z 境界間の有効スラブの XY union 面積］× 区間高さ
```

評価結果 `nullopt` は印刷領域外、モデル衝突、ベッド除外領域との交差、サポート幾何生成失敗などの評価不可を表す。`0 mm³` は有効な候補である。

## 順位、改善判定、終了状態

現在姿勢の評価値を基準 `baseline_volume` とする。`current_volume_mm3` が有効ならそれを基準にできるが、GUI は NaN を渡してワーカー内で現在姿勢を測る。体積の同値幅は `epsilon = max(1 mm³, baseline × 0.001)`。最良体積からこの幅に入る候補同士は、まず `|Δy|` が小さい方、次に現在姿勢からの回転距離が小さい方、最後に正規化角と Δy の順で選ぶ。**採用条件は `winner_volume < baseline_volume − epsilon`**。満たさなければ `Unchanged` とし、現在姿勢を保持する。

`PlacementStatus` は `Improved`、`Unchanged`、`Canceled`、`InvalidConfig`、`NoFeasiblePose`、`ResourceExhausted`。候補評価中の例外は当該候補の失敗として処理され得るが、現在姿勢の評価失敗は探索を終える。キャンセルは最終順位付け前にも再確認し、キャンセル後の勝者を UI に適用しない。

## 並列実行とメモリ制御

候補は角度ごとにまとめられ、異なる角度群を TBB で並列評価する。`angle_group_concurrency = 1` は逐次、正数は固定上限、`0` は資源状況に応じた自動調整で、GUI は 0 を使う。自動調整は最初の角度群を一つ実行してメモリ増分を測り、その概ね 2 倍または最低 0.5 GiB を次の群の見積りとする。利用可能メモリから **2 GiB または総メモリの 20% の大きい方** を予約し、プロセス RSS が総メモリの約 75% に近づく候補も抑える。CPU 使用率に余裕があれば同時群数を増やす。メモリ不足時は待機状態を表示し、サンプリング不能なら一群で進む。`bad_alloc` は `ResourceExhausted` として終了する。これらは資源保護の実装値で、最適化品質の数学的条件ではない。

進捗段階は現在姿勢評価、候補準備、粗探索、局所探索、メモリ待機、終了処理。パーセントは概ね `0–5`、粗探索 `5–75`、局所探索 `75–99`、終了 `100` に対応する。複数ワーカーからの候補完了通知は同期して集計する。

## GUI への反映と安全性

`DynaPinPlacementJob::finalize()` は `Improved` かつ非キャンセル・例外なしの場合だけ適用 callback を呼ぶ。UI 側は現在プレート番号、`Print` の modified count、対象 object/instance ID、初期変換行列がスナップショットと一致することを再検証する。一致すれば Undo スナップショットを一回取り、対象インスタンスだけを変換してシーンを再読込する。不一致なら古い探索結果を捨てる。

通常の `reslice()` の直前に探索を挟み、終了後は一回限りの `dynapin_placement_reslice_guard` を立てて `reslice()` を再実行する。これにより改善後の配置で通常スライスが走り、探索が再帰起動しない。`Unchanged` や `NoFeasiblePose` でも元のスライス要求は一回継続する。キャンセル、例外、資源枯渇ではこの継続を止める。すでに有効なスライス結果を再利用する場合は、明示的な強制探索要求がない限り探索を開始しない。

## 実装上の境界と確認事項

探索とスコアは `src/libslic3r/DynaPinPlacement.hpp/.cpp`、幾何専用生成の入口は `Print.cpp`/`PrintObject.cpp`/`SupportMaterial.cpp`、非同期ジョブは `src/slic3r/GUI/Jobs/DynaPinPlacementJob.*`、起動・適用・再スライスは `Plater.cpp` にある。`PlacementResliceAction` は GUI の状態遷移を表すのに libslic3r に置かれており、責務の境界を見直す余地がある。

現在のスコアは体積の代理指標なので、押出量・造形時間・ピン上の定着性を直接予測しない。自動選択対象は Normal サポートに限る。角度群でスライス準備を再利用する実装のため、単体評価との同値性と候補間の状態復元は変更時の重要な回帰点である。既存テスト `tests/libslic3r/test_dynapin_placement.cpp` は区間、候補、体積 union、同点・改善判定、角度別評価、キャンセル、進捗、メモリ制御を扱う。実モデルでは最終 G-code と安全なピン選択も別途確認する。
