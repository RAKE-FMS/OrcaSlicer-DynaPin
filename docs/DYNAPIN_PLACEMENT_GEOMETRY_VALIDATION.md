# 位置・回転最適化のGeometry only評価

検証日: 2026-10-23、macOS arm64、Release。

## 動作

- `SupportGeometryMode::Exact` が既定。通常スライスの生成処理は従来どおり。
- 最適化の候補探索は `PlacementSearch` を指定する。外周とインフィル領域準備を残し、カール推定とアイロニングを省略する。Normalの `thick_bridges && independent_support_layer_height` の場合だけインフィル経路も残す。
- Treeは枝・領域・着地層まで生成し、経路の代わりに領域で着地と干渉を判定する。ピン除外後の再生成にも同じモードを使用する。
- Treeを含むシーンでは、現配置と上位5候補を従来の経路生成で再評価する。最終スコアはこの厳密評価の体積。比較基準が不成立の場合や、キャンセル・メモリ不足の場合は適用しない。
- 体積の集計、探索範囲、並列制御、JSON設定は変更していない。

## 対象テスト

```sh
cmake --build build/arm64 --config Release --target fff_print_tests libslic3r_tests --parallel 2
build/arm64/tests/libslic3r/Release/libslic3r_tests.app/Contents/MacOS/libslic3r_tests '[DynaPinPlacement]'
build/arm64/tests/fff_print/Release/fff_print_tests.app/Contents/MacOS/fff_print_tests '[DynaPinGeometry]'
```

最適化の27ケース・161項目、形状生成と状態保持の4ケース・339項目が成功した。

`cmake --build build/arm64 --config Release --target OrcaSlicer --parallel 2` も成功し、Releaseアプリを再生成した。GUIでの手動スライス操作は未検証。

Normalはブリッジ有無・厚いブリッジ・独立サポート層高さの組合せで、従来方式と候補探索方式の体積とピン選択が一致した。TreeのSlim/Strong/Hybridで、領域が生成され、押出経路が生成されないことを確認した。

最終検証は、不成立候補の除外、順位逆転、改善なし、同点、有意差未満、5候補上限、現配置不成立、最終候補でのキャンセルを検証した。合成スコアを使う既存の並列テストも、最終的に実シーンの厳密スコアが採用されることを確認するよう更新した。

候補評価前後で、元のPrintのサポート経路の座標列とピン選択が一致した。Normalでは出力時刻コメントを除くG-codeも一致した。TreeのG-code再出力には経路順序の差が生じるため、Treeのバイト一致は未確認であり、経路データの不変性を検証対象とした。

## 性能計測

隠しベンチマークは3角度（0/5/355度）・Y方向1ピッチに探索を限定する。局所探索もこの3角度だけを評価する。これは全72角度の実行時間を表すものではない。角度グループの同時実行数は1とし、従来方式と新方式を各3回計測した。

```sh
DYNAPIN_BENCHMARK_FIXTURE=Simple_Bridge.3mf DYNAPIN_BENCHMARK_EXACT=1 \
  build/arm64/tests/fff_print/Release/fff_print_tests.app/Contents/MacOS/fff_print_tests '[.DynaPinGeometryBenchmark]'
DYNAPIN_BENCHMARK_FIXTURE=Simple_Bridge.3mf \
  build/arm64/tests/fff_print/Release/fff_print_tests.app/Contents/MacOS/fff_print_tests '[.DynaPinGeometryBenchmark]'
```

| Simple Bridge（中央値） | 従来方式 | 新方式 |
|---|---:|---:|
| 探索 | 6.517秒 | 2.958秒 |
| 最終検証 | なし | 0.755秒 |
| 全体 | 6.517秒 | 3.628秒 |
| 最終評価体積 | 2837.73 mm³ | 2837.73 mm³ |

全体時間は約44%短縮した。全体と各段階の中央値は個別に算出したため、中央値同士の和は全体の中央値と一致しない。

別プロセスで各方式を3回実行し、`/usr/bin/time -l` で取得したピークRSSは従来104,415,232 bytes、新方式109,821,952 bytesだった。今回の変更によるピークメモリ削減は確認していない。

### 未完了の受け入れ条件

- Arch Bridgeは現在の初期配置をTreeに切り替えると、現配置が不成立となり探索が始まらなかった。3回の終了時間を速度改善として扱っていない。
- 2026-10-23時点ではGymnastの計測は中断した。3秒間のサンプリングでは主スレッドの2168サンプル中1880が既存の `select_tree_pins()` 配下にあり、投影とポリゴン合併が支配的だった。10月24日の追加対応と計測は末尾に記載する。
- したがって、3モデルすべてでの速度改善という受け入れ条件は未達成。全角度探索についても改善率を確認していない。

## 既存テストの失敗

変更前の保存済みテスト実行ファイルでも、現在の設定でDynaPin関連85ケース中10ケースが失敗した。限定探索テストでは、期待するY移動0に対し、変更前から-0.19375が選ばれていた。検証中の作業ツリーには、別途変更された `kp3s.json` の `pull_origin.z = 4.5` があり、ピン高さや採用ピンを固定値で検証する失敗も含まれる。この設定変更には手を加えていない。

最終の広いスイートは89ケース中79成功・10失敗で、失敗したケースと48項目の失敗数は変更前と一致した。今回追加した4ケースの失敗はない。

複数高さの着地テストは、変更前・変更後の単独実行で各748項目が成功した。広いスイートでは同テストに実行順序依存の座標範囲エラーも観測したため、スイート全体が成功したとは扱っていない。

## 2026-10-24: GymnastのTreeピン投影

実際のGUIログでは、位置・回転探索が393秒・314評価でキャンセルされていた。角度グループの同時実行数は4で、メモリ待ちは0msだった。候補ごとのピン投影に約8〜10秒かかり、308層の接触領域を追加するたびに、増大した投影全体を `union_()` していた。

次の2点で重複計算を減らした。探索範囲・候補数・衝突判定は変更していない。

1. 接触領域の合併は次のピン・モデル判定までまとめ、最後のピンより下の領域処理を省く。
2. ピン着地面との交差計算では、着地面の外接矩形と離れた投影ポリゴンを除く。矩形が接するものは残し、従来のポリゴン交差で判定する。外接矩形は1回の投影選択の中だけで再利用し、領域の合併・差分で更新する。

高さごとの接触領域をY候補間で再利用する案も計測したが、限定探索は78.014秒（探索71.435秒、最終検証6.579秒）で追加効果が認められず、最終実装から外した。

全角度のサンプリングで残る交差計算も確認し、既存の `intersection_clipped()` を使う案を試した。参照とのピン選択は一致したが、限定探索の3回計測は38.862／36.022／33.336秒（中央値36.022秒）で、後述の32.733秒を上回ったため採用していない。

第1段階だけのGymnast限定探索（3角度・289評価、同時実行数1、最終検証を含む）の3回計測は次のとおり。
