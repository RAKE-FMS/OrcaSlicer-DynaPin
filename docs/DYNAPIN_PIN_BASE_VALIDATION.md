# ピン上の定着用サポート初層：検証記録

[現行仕様と変更理由](DYNAPIN_PIN_BASE.md)の検証記録。

検証日：2026-10-22。比較元は `7835b76141` と作業開始時点の既存変更を含むビルド。

## 実装と自動検証

- ピン着地部分の最初の実サポート層だけを通常サポートに置換し、既存の初層密度・拡張量・線幅・速度を適用する。下部インターフェース層数には依存しない。
- 層厚はピン上面から各押出面までの実際の高さを使う。経路を線幅の半分だけ内側に制限し、モデル・造形範囲・他ピンのブロッカーで生成領域を切り取る。
- 通常サポート、tree_slim、tree_strong、tree_hybridで確認した。下部層数0/1/2/3/−1、再スライス、オブジェクトの密度・拡張量上書き、複数ピン、異なるピン高さ、可変層高、短いサポート、小さな着地面を含む。
- 最終G-codeのテストではサポート材をT1、インターフェース材をT0に分け、対象押出がT1・初層速度以下・ファン0%であることを確認した。ファン先行起動0.5秒、キックスタート0.3秒も有効にした。
- Releaseの`fff_print_tests`と`OrcaSlicer`をビルド。外縁余白追加前の回帰テストは49件、50,345項目すべて成功した。

回帰テストのフィルター：

```text
[DynaPin]~[.]~"DynaPin Tree selects pins after applying an optimized pose"~"DynaPin Tree bounded search preserves final pins across concurrency limits",[SupportMaterial]~[.],[Cooling],[LandingOrder],[LandingBase]
```

上記の配置最適化2件は、変更前でも失敗することが確認されている既存の不安定なテストとして除外した。一括実行の初回には新しいG-codeテストのフィラメント判定も一度失敗したが、再実行で保存した出力はT1であり、その後の一括実行3回（失敗時と同じ乱数シード、および診断コード削除後を含む）では再現しなかった。原因は未特定。

## 外縁余白1.2 mmの追加

`support_exclusion.landing_edge_inset_y`を任意項目として追加し、KP3Sでは1.2 mmに設定した。同じ高さの連続ピンは共有境界を残して結合し、定着用初層の外縁だけを縮める。元の初層からも切り取った端の領域を除去する。省略時の余白は0 mm。

- 単独・連続2本・連続3本・途中欠け・高さ違い・ローカル座標の移動を確認。連続3本の幅は`12.4 × 3 − 2.4 = 34.8` mm。
- 通常サポートと対応ツリー／ハイブリッドでピン端に寄せた形状を確認。C++回帰テスト51件・50,664項目が成功し、Releaseアプリのビルドも完了した。
- Simple_Bridgeの最終G-codeで、押出幅を含む着地範囲がY=67.8〜102.6 mm（34.8 mm）となり、対象押出中のファン0%を維持した。DynaPin無効時は生成日時のコメントを除いて完全一致した。
- 外縁余白追加前と比較し、総フィラメント長は7,751.206→7,745.360 mm、サポート用は680.195→674.349 mm、推定時間は3,555.639→3,548.558秒となった（材料−5.846 mm、時間−7.081秒）。
- 全140ピン×4モードの引き出しG-codeは追加前後で一致した。Pythonの引き出し動作テストは18件中4件が失敗したが、`7835b76141`のJSONでも同じ4件が失敗することを確認した。既存のYオフセット期待値との不一致であり、今回の範囲では変更していない。
