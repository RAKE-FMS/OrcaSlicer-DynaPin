# DynaPin対応・Δy／Z回転配置最適化 設計

## 目的

DynaPinを使用するNormalサポート印刷で、選択中の1インスタンスについて、Δxを変更せず、Z軸回転とΔy移動を探索し、DynaPin適用後のサポート関連幾何体積を最小化する。

対象条件は、DynaPin有効、ピン自動選択、Normalサポート、選択中の1インスタンスとする。Manualピン、Tree/Organic、複数選択は対象外とし、通常のスライスを継続する。

## 姿勢探索

現在姿勢を基準に相対Z回転0～355°を5°刻み、Δyを1ピッチの1/16刻みで粗探索する。現在姿勢は可能な場合に必ず評価する。体積の小さい上位5候補について、角度を1°刻み、Δyを局所的に再探索する。

回転中心は現在のワールド座標上のモデル中心とする。Δxは探索変数にしない。実装上は回転中心を維持するための姿勢補正としてインスタンスのXオフセットを調整するが、X方向の独立した候補探索は行わない。候補は一時的なModel/Printで評価する。

角度ごとのΔy探索範囲は基本的に[-pitch/2, +pitch/2]とする。ビルド領域によって片側が切れる場合は、その幅を反対側へ移し、可能な限り合計1ピッチを確保する。両側が制限される場合は実行可能な最大区間だけを使う。回転後のX方向逸脱はΔxで補正せず候補を無効にする。

## 制約とピン形状

他モデル・他インスタンスは固定障害物とし、ビルド領域、引き出し経路、ピン先端干渉領域と交差する候補を無効にする。現在姿勢がピン先端と交差する場合は最適化を中止して警告する。

KP3Sの先端干渉領域は、各物理ピンを中心とする直方体とする。

- X: 0～20 mm（設定上はx_min～x_max）
- Y: 既存の物理ピン中心から±width_y/2
- Z: ピンZ中心から±2.5 mm
- 安全余白: 全方向1 mm

設定例:

```json
"tip_collision": {
  "x_min": 0.0,
  "x_max": 20.0,
  "width_y": 12.4,
  "thickness_z": 5.0,
  "clearance": 1.0
}
```

既存のサポート除外形状、ピン上面での下方伝播終了、blockerの固有Z範囲は維持する。blockerのz_minを0へ拡張しない。

## 評価値

候補ごとに、DynaPin自動選択とNormalサポート領域生成まで実行する。押出経路やG-codeは生成せず、領域生成結果をZ方向のスラブごとにunionして体積を求める。比較値は候補Print全体のサポート関連体積とする。

対象領域はtop contacts、bottom contacts、intermediate、interface、base interfaceとし、raftは除外する。同じZスラブで重なる領域は一度だけ計上する。

```text
support_volume = Σ union(active_support_polygons).area × slab_height
```

候補の比較は体積、次に|Δy|、最後に現在姿勢からの回転量で行う。体積差がmax(1 mm³、現在体積の0.1%)以内なら同値とし、現在姿勢より有意に改善しない場合は姿勢を変更しない。

## 実行と適用

GUI側のキャンセル可能なバックグラウンドジョブで、作業用Model/Printを使って探索する。候補評価ではスライス面とサポート領域だけを生成し、ライブのUIモデルは探索中に変更しない。

成功時だけUIスレッドでUndoスナップショットを1回作成し、対象インスタンスへZ回転とΔyを適用してスライスを再開する。最適化による再スライスでジョブが再帰起動しないよう、一回限りのガードを使用する。入力署名の永続キャッシュは今後の改善対象とする。

## 検証

- 既存のDynaPin Z回転再利用回帰テストが通ること
- Geometry評価が押出経路を生成しないこと
- raftを除外し、Zスラブの重複を二重計上しないこと
- Δyの片側補填と両側制限が仕様どおりであること
- ピン先端のX/Y/Z境界と安全余白が正しく判定されること
- 現在姿勢の干渉では中止し、探索中の干渉では候補だけを除外すること
- 選択インスタンスだけが変換され、他インスタンスが固定されること
- 自動適用後に最適化が再帰しないこと
- DynaPinのblocker Z範囲と下方伝播終了処理が維持されること
- `gymnast.3mf`で適用前後の体積、Δy、回転角、選択ピンを比較すること

## レビュー時点の既知の問題と残課題

2026-08-27時点のステージ済み実装をレビューした結果、関連テストは通過しているが、以下は未解決である。これらを解消するまで、DynaPinの下方伝播処理を完了扱いにしない。

### 1. コンタクト単位の投影分割による遮断漏れ（解決済み）

`SupportMaterial.cpp` の `ProjectionState` はコンタクトごとに作られ、ピン上面による差し引きは投影がその高さを通過した state にだけ適用される。上部オーバーハング由来の投影が複数 state に分割され、その一部がピン上面より下で生成された場合、その state がピンの blocker 範囲を下方向へ通過する可能性がある。

安全なピンに到達した state は、そのピン領域を差し引いたまま終了させる。ピン下で同じポリゴンを再追加する `resume_z` / `DeferredTermination` は使用しない。後から検出された独立した下部オーバーハングだけを新しい state として追加する。この方針を実装し、積層ピンの blocker 範囲内にサポートが残らない回帰テストと実モデルの再スライスで確認した。

### 2. 回帰テストの形状カバレッジ不足

`tests/fff_print/test_support_material.cpp` の追加テストは、浮遊スラブの XY 範囲と KP3S の DynaPin blocker 領域が確実に重なることを保証していない。したがって、blocker 内のサポートがないという結果が、DynaPinの遮断処理ではなく、形状の非重複や境界・グリッド拡張によって成立する可能性がある。

テストは、ピン領域と実際に重なる浮遊形状を使い、次の三点を同時に確認する。

- blocker 内にサポートが存在しない
- ピン上面より上には必要なサポートが存在する
- 独立した下部オーバーハングのサポートは必要な範囲で残る

自動選択テストも、選択ピンと blocker 数だけでなく、選択結果を使った実際のサポート形状を検証する。

### 3. 通常サポートへの形状・性能影響

DynaPin が無効な場合も、コンタクトごとに `project_support_to_grid()` を呼ぶ経路になっている。グリッド化は一般に union と可換ではないため、従来の集約投影とサポート形状が変わる可能性がある。また、投影 state 数に応じて計算量が増える。

DynaPin 無効時は従来の集約経路を維持する fast path を追加し、DynaPin 有効時も集約投影との差分と処理時間を回帰確認する。

### 4. 自動検出時の `sharp_tails` 副作用

自動ピン検出と通常のサポート生成の双方が `top_contact_layers()` を呼び出す。`top_contact_layers()` は共有 `Layer::sharp_tails` に追加するため、同一スライス内の再呼び出しや自動選択の再実行で同じ sharp tail が重複登録され、サポート結果が変化する可能性がある。

検出処理を副作用なしにする、または sharp tail の重複登録を防ぐ。自動選択の再実行を含む回帰テストを追加する。

### 5. デバッグステージとピン選択・G-code の不整合

`dynapin_debug_stage = 0` は Standard support を意味するが、ピン選択と G-code の pull 処理はこの値を参照しない。そのため、サポート生成ではDynaPinを無効にしていても、選択済みピンの pull G-code が出力される可能性がある。また、環境変数による debug stage 上書きも、選択処理と G-code 出力には反映されない。

debug stage の定義をサポート生成、ピン選択、G-code 出力で統一し、stage 0 でDynaPinの副作用が発生しないことを確認する。

### 6. 診断用 BoundingBox の集計不備

`detect_dynapin_pins()` のレイヤー内 BoundingBox 集計が、レイヤー単位の初期化フラグではなく全体用のフラグを参照している。これは主にデバッグ出力の誤りだが、レイヤーごとの投影範囲を正しく報告できない。レイヤー用フラグを分離する。

### 完了条件

上記の問題を修正し、ピン領域とサポート領域が確実に重なる決定的な fixture で、DynaPin 有効・無効、単一・積層オーバーハング、自動選択の再実行を検証する。関連テストだけでなく、通常サポートの回帰テストと実際の `gymnast.3mf` スライスでも形状・処理時間・G-code を確認する。

## 2026-08-27 テスト失敗の切り分け

作業中に報告されたテスト失敗は、実装回帰と手順・期待値の失敗を分けて扱う。現在のarm64構成には汎用の `tests` ビルドターゲットがなく、FFFテストは `fff_print_tests` を直接ビルドする。上段投影をピン下で再開することを期待したアサーションは仕様誤りだったため、下段由来の独立コンタクトを検証する期待値へ改めた。G-codeの再処理をテストケース内へ組み込む試みはテストハーネスのライフサイクルを誤るとSIGSEGVになるため、サポート幾何のCTestとCLIによる実G-code検証を分離する。

再発時は、まず `cmake --build build/arm64 --target fff_print_tests --parallel` と `ctest --test-dir build/arm64 --output-on-failure -R 'DynaPin|fff_print'` を実行する。全CTestのネットワーク／SSL失敗や、CLIのリソース不足によるクラッシュを、DynaPinのサポート投影失敗として数えない。
